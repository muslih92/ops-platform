# منظومة إدارة وتمكين فريق التشغيل

منصة ويب عربية (RTL) لإدارة وتمكين فرق التشغيل: المواقع والمحطات، الورديات، المهام، المهارات، والتطوير.
تطبيق مستقل: **Node.js (Express) + PostgreSQL** في الخادم، و**React + TypeScript + Tailwind** في الواجهة. لا يعتمد على أي منصة بناء خارجية.

> المنصة للإدارة والتوثيق فقط. لا تحتوي على أي أمر تشغيل للمضخات أو الصمامات أو SCADA.

---

## المحتويات

```
db/migrations/   مخطط قاعدة البيانات والصلاحيات (RLS) وسير العمل والبيانات الأساسية
db/seed/demo.sql بيانات تجريبية وهمية ومعلَّمة (is_demo)
server/          الخادم: الدخول والجلسات وواجهة CRUD العامة والملفات والاستيراد والتقارير والمهام الدورية
server/scripts/  إنشاء المدير الأول، مستخدمو العرض التجريبي، اختبار سير العمل
web/             الواجهة (18 صفحة)
```

## التشغيل السريع (Docker)

```bash
cp .env.example .env          # عدّل DB_PASSWORD وباقي القيم
echo "DB_PASSWORD=$(openssl rand -hex 16)" >> .env
docker compose -f docker-compose.yml -f docker-compose.build.yml up -d --build
docker compose exec app node server/scripts/create-admin.js admin@your-org.sa "اسم مدير النظام"
```

ثم افتح `http://SERVER:3100` (غيّره بالمتغير `APP_PORT`). على Hostinger Docker Manager استخدم «الكتابة من عنوان URL» مع رابط ملف `docker-compose.yml` الخام وعيّن `DB_PASSWORD`؛ الصورة تُبنى تلقائيًا في GitHub Actions إلى `ghcr.io/muslih92/ops-platform`. بعد تفعيل HTTPS عيّن `COOKIE_SECURE=true`. ضع المنصة خلف وكيل عكسي يقدّم HTTPS (مثل Nginx) قبل استخدامها خارج الشبكة المحلية؛ ملف تعريف الجلسة يكون `Secure` في وضع الإنتاج.

## التشغيل بدون Docker

المتطلبات: Node.js 20 أو أحدث، PostgreSQL 14 أو أحدث (مجرّب على 16).

```bash
npm install && npm --prefix web install
export DATABASE_URL=postgres://ops_owner:PASS@localhost:5432/ops
npm run migrate                 # ينشئ الجداول والدور app_user والسياسات
npm run build                   # يبني الواجهة إلى web/dist
npm run create-admin -- admin@your-org.sa "اسم المدير"   # يطلب كلمة المرور (أو ADMIN_PASSWORD)
npm start                       # http://localhost:3000
```

للتطوير: `npm run dev:server` و`npm run dev:web` (الواجهة على 5173 وتمرر `/api` إلى 3000).

### متطلبات مستخدم قاعدة البيانات
- مالك الجداول (ينفذ الترحيلات) ويملك صلاحية `CREATEROLE` في أول ترحيل لإنشاء الدور `app_user`.
- كل طلب يُنفَّذ داخل معاملة بـ `SET LOCAL ROLE app_user` مع هوية المستخدم، فتُطبَّق سياسات RLS على كل جدول (مفعّلة بـ FORCE).
- يُفضَّل ألا يكون المالك superuser في الإنتاج، وألا يُمنح `BYPASSRLS`.

## المدير الأول (آمن)
- الطريقة الموصى بها: `npm run create-admin -- email "الاسم"`. كلمة المرور لا تُمرَّر في سطر الأوامر.
- بديل للتجربة فقط: عند `FIRST_USER_IS_ADMIN=true` يصبح أول حساب يُسجَّل مديرًا (بقفل يمنع التسابق). أبقِه `false` في الإنتاج مع `ALLOW_SIGNUP=false`.
- الحسابات الجديدة المسجلة ذاتيًا تبقى "بانتظار التفعيل" بلا أي صلاحية حتى يمنحها المدير دورًا.

## البيانات التجريبية
```bash
npm run seed:demo
DEMO_PASSWORD='كلمة-مرور-قوية-123' npm run demo-users
```
تنشئ 17 موقعًا و23 وردية و36 موظفًا باسم "موظف تجريبي NN" وبريد `@example.invalid` وأرقام هواتف وهمية، مع مهام وإجازات وتسليم ومهارات وخطط. كل السجلات معلَّمة بشارة "تجريبي". الحسابات: `ops.manager@demo.local`، `supervisor@demo.local` (مشرف PS1–PS3 وHPT)، `employee@demo.local`، `cr.employee@demo.local`، `reports@demo.local`.

لا تشغّل البيانات التجريبية على قاعدة الإنتاج. لحذفها لاحقًا استخدم قاعدة جديدة، أو احذف السجلات التي `is_demo = true`.

## الاختبار
```bash
BASE_URL=http://localhost:3000 DEMO_PASSWORD=... ADMIN_EMAIL=... ADMIN_PASSWORD=... npm test
```
يتحقق من: التسليم والاستلام وتحويل الملاحظة لمهمة، دورة الإجازة مع منع الاعتماد الذاتي وطلب التجاوز الموثق، التقييم وسريته، صلاحيات قارئ التقارير، حماية صلاحيات المدير، وصدق حالة التكاملات. **ينشئ سجلات**، فشغّله على قاعدة تجريبية فقط.

## الأدوار
| الدور | النطاق |
|---|---|
| مدير النظام | كل شيء، بما فيه المستخدمون والصلاحيات والإعدادات وسجل التدقيق |
| مدير التشغيل | كل المواقع: الموظفون والمهام والإجازات (بما فيها تجاوز التغطية) والتطوير والتقييم والتقارير |
| مشرف الموقع | المواقع المسندة إليه وما يتبعها فقط |
| موظف | ملفه ومهامه وإجازاته وتسليماته ومبادراته وتقييمه بعد إرساله |
| قارئ التقارير | التقارير فقط، دون بيانات الاتصال أو سجل التدقيق |

مصفوفة الصلاحيات قابلة للتعديل من صفحة "المستخدمون والصلاحيات"، والتطبيق الفعلي في قاعدة البيانات.

## متغيرات البيئة
انظر `.env.example`. أهمها: `DATABASE_URL`، `UPLOAD_DIR` (مكان حفظ المرفقات والشعار، احفظه في نسخ احتياطي)، `ALLOW_SIGNUP`، `FIRST_USER_IS_ADMIN`، `TRUST_PROXY`.

## ما يحتاج إعدادًا خارجيًا
| البند | الحالة الحالية | المطلوب |
|---|---|---|
| SAP PM | غير مهيأ. أرقام البلاغات وأوامر العمل تُحفظ يدويًا كمراجع | واجهة OData/RFC معتمدة من فريق SAP، حساب خدمة، ثم برمجة المزامنة. المتغيرات `SAP_PM_*` تتيح اختبار الوصول فقط |
| SCADA | غير مهيأ. الإنذارات تُوثَّق يدويًا | واجهة قراءة فقط من Historian معتمدة من الأمن السيبراني. لا أوامر تحكم إطلاقًا |
| البريد الإلكتروني | غير مهيأ. الإشعارات داخل المنصة فقط | خادم SMTP وحساب إرسال، ثم برمجة قناة البريد |
| WhatsApp | غير مهيأ | مزود WhatsApp Business API واعتماد رسمي |
| الاستضافة وHTTPS | — | خادم داخلي أو سحابي، شهادة TLS، وكيل عكسي |
| PostgreSQL والنسخ الاحتياطي | — | قاعدة مُدارة أو خادم، مع نسخ احتياطي دوري لقاعدة البيانات ومجلد `UPLOAD_DIR` |
| تسجيل الدخول الموحد (SSO) | غير متوفر | يمكن إضافته لاحقًا (Azure AD/SAML) |
| اللغة الإنجليزية | البنية جاهزة (قاموس في `web/src/lib/i18n.ts`) | إضافة الترجمة |

زر "اختبار الاتصال" في صفحة التكاملات يتحقق من وجود المتغيرات وإمكانية الوصول للعنوان فقط، ويعرض الحالة بصدق (غير مهيأ، متصل، فشل آخر اتصال). لا توجد مزامنة فعلية في هذا الإصدار.

## ملاحظات أمنية
- كلمات المرور bcrypt (تكلفة 12)، 10 أحرف على الأقل بحروف وأرقام، مع إبطاء محاولات الدخول المتكررة.
- الجلسات في قاعدة البيانات (رمز مُجزّأ)، ملف تعريف `httpOnly`، وحماية CSRF عبر ترويسة مخصصة.
- لا مفاتيح أو أسرار في الواجهة. سجل التدقيق لا يُعدَّل ولا يُحذف من التطبيق، ولا يخزّن كلمات المرور.
- الأرشفة بدل الحذف لمعظم السجلات، مع إمكانية الاستعادة.
- المنطقة الزمنية الافتراضية Asia/Riyadh في الخادم والواجهة.
